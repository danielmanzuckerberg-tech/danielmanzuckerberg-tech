# Alpha OTP

> Архитектурный концепт · Authentication · Публичного работающего сервиса пока нет

## Задача

Спроектировать одноразовое подтверждение действия без хранения кодов в открытом виде и без бесконечных попыток проверки. OTP не заменяет полноценную модель аутентификации и оценки риска.

## Устройство

API принимает запрос от уже определённого клиента и проверяет лимиты по владельцу, получателю и источнику. Криптографически случайный код связывается с назначением, сроком действия и счётчиком попыток. В хранилище попадает HMAC кода с серверным ключом, а доставка уходит в очередь.

Подтверждение выполняется атомарно: проверка срока, счётчика и одноразовости не должна расходиться между параллельными запросами. Успех завершает только то действие, для которого выпущен код.

## Критерии готовности

- [ ] Криптографическая генерация и безопасное сравнение
- [ ] Согласованная проверка и погашение кода
- [ ] Общий лимит попыток, включая одновременные запросы
- [ ] Повторы доставки без создания нового намерения
- [ ] Маскированные логи без кода и полного получателя
- [ ] Тесты истечения, повторного использования и конкуренции

## Границы

SMS уязвим к перевыпуску SIM и не подходит как универсальный сильный фактор. Для чувствительных сценариев нужны дополнительные меры и выбранная по риску схема входа. Здесь описан проект, а не заявлена сертифицированная система безопасности.
