# Luffy SMS

> Архитектурный концепт · Messaging · Публичного работающего сервиса пока нет

## Задача

Построить понятный жизненный цикл разрешённых транзакционных SMS: от запроса отправки до подтверждённого результата. Получатель должен ожидать сообщение; массовые нежелательные рассылки не входят в назначение проекта.

## Устройство

API фиксирует намерение и outbox-запись в одной транзакции. Обработчик отправляет сообщение провайдеру со стабильным ключом и ограниченным бюджетом повторов. Подписанные webhook-события обновляют статус с учётом дубликатов и возможного нарушения порядка доставки.

Важное различие: «принято», «отправлено провайдеру» и «доставлено» — разные состояния. Интерфейс не должен показывать доставку только потому, что внешний API ответил успешно.

## Критерии готовности

- [ ] Идемпотентный приём и надёжный outbox
- [ ] Проверка согласия, назначения сообщения и лимитов расходов
- [ ] Очередь с конечными повторами и карантином
- [ ] Проверка подписи и дедупликация webhook
- [ ] Маскирование персональных данных
- [ ] Сценарии задержанной, повторной и неупорядоченной доставки
