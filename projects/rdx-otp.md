# RDX OTP

> Архитектурный концепт · Authentication · Публичного работающего сервиса пока нет

## Задача

Исследовать протокол подтверждения, который сохраняет однозначный результат при повторах, тайм-аутах и одновременной проверке одного кода.

## Устройство

В основе — машина состояний подтверждения: создано, отправляется, доступно для проверки, подтверждено, истекло. Идентификатор операции принадлежит конкретному владельцу и назначению. Код никогда не является единственным основанием для выбора чужой операции.

Запрос на подтверждение имеет ключ идемпотентности. После успешной атомарной проверки повтор возвращает сохранённый результат для того же владельца, но не выполняет связанное действие заново.

## Критерии готовности

- [ ] Определён контракт каждого состояния
- [ ] Неверный и истёкший код не раскрывают лишние сведения
- [ ] Один ключ с разным телом вызывает конфликт
- [ ] Сроки хранения результата документированы
- [ ] Два параллельных подтверждения не создают два эффекта
- [ ] Есть восстановление после сбоя между этапами

## Чем отличается от Alpha OTP

Alpha OTP фокусируется на жизненном цикле и защите самого кода. RDX OTP — на надёжном протоколе обработки подтверждения. Это два проектных направления, а не две объявленные готовыми платформы.
